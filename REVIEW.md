# Code Review

## Findings

| # | Where | What was wrong | How to reproduce or notice it | How it was fixed |
|---|---|---|---|---|
| 1 | `/health`, startup | Health returned `ok` without contacting MongoDB, and the client was created at import time. A running API could therefore claim readiness while the database was down. | Stop MongoDB and call `GET /health`; the starter still returned 200. | Create the client during lifespan startup, ping MongoDB, create indexes, and return 503 when the ping or index setup fails. |
| 2 | Index setup | No application indexes were created. The natural keys were not unique in MongoDB, and list/analytics queries lacked suitable indexes. | Inspect `getIndexes()` in a fresh database; only `_id_` existed. Concurrent inserts could also create duplicate records. | Add idempotent unique natural-key indexes and indexes for employee lookup, list sorting/filtering, punch-out lookup, and analytics. |
| 3 | `EmployeeIn`, `create_employee` | Employee code, email, dates, shift strings, lengths and equal shift times were not validated. `created_at` used local naive time and was returned as a BSON-style datetime rather than epoch milliseconds. | Submit `emp_code: "x"`, an invalid email/date, or identical shifts; inspect response `created_at`. | Add contract validation, store a UTC timestamp, and serialize the creation time as epoch milliseconds. |
| 4 | `create_employee` | A read-before-insert duplicate check was race-prone. Two concurrent requests could both pass the check. | Send parallel creates with one `emp_code`. | Enforce uniqueness in MongoDB and translate `DuplicateKeyError` to 409. |
| 5 | `list_employees` | The skip was `page * page_size`, which skipped page one; results were not sorted; `total` counted all employees instead of the department filter; page inputs had no bounds. | With three matching rows, request page 1 of size 1 and compare total/order. | Use `(page - 1) * page_size`, sort by `emp_code`, count the filtered query, and validate page and page size. |
| 6 | `punch_in` | Unknown employees caused a subscript error, timestamp `0` fell through to “now,” seconds/floats/strings were not rejected, and timestamps used the machine's local timezone. | Punch for an unknown employee; send a seconds-looking timestamp or punch around midnight IST. | Return 404 for unknown employees, validate epoch milliseconds and range, and convert/truncate UTC instants explicitly. |
| 7 | `punch_in`, `_attendance_date` | The attendance date was the host-local date, and overnight punches before shift end were not assigned to the prior shift date. | For a 22:00-06:00 shift, punch in at 02:00 IST and inspect `date`. | Determine the attendance day in IST, applying the prior-day rule for overnight shifts. |
| 8 | `compute_late_minutes` | The grace check used floored minutes (`> 10`), so 09:40:01 was not late; it also anchored an overnight shift start to the wrong day. | For a 09:30 shift, test 09:40:00 and 09:40:01; test an early-morning overnight punch. | Compare elapsed seconds strictly against 10 minutes, floor whole minutes only after the grace check, and anchor shift start to the attendance day. |
| 9 | `punch_in` | Check-then-insert did not protect one employee/date from simultaneous requests; the status was not restricted to presence statuses. | Send simultaneous punch-ins or use `status: "ABSENT"`. | Validate the status and rely on the unique `(emp_code, date)` index for an atomic conflict. |
| 10 | `compute_work_hours` | Python `round()` uses ties-to-even and floating-point rounding, not the required decimal half-up rounding. | Test a duration whose hour value is exactly halfway between two hundredths. | Use `Decimal` and `ROUND_HALF_UP` after computing elapsed whole seconds. |
| 11 | `compute_overtime` | The starter counted any positive overtime, including less than 30 minutes, and anchored overnight shift end to the attendance date rather than the next date. | Punch out 29 minutes after shift end; test 06:40 for a 22:00-06:00 shift. | Anchor shift end correctly and count only whole overtime minutes when the floor is at least 30. |
| 12 | `list_attendance` | It loaded and sorted the entire collection in Python, making it unsuitable for 100,000 records. Its sort omitted the required employee-code tie-break; page inputs and reversed date ranges were unchecked. | Inspect the query plan and request a second page; use `date_from > date_to`. | Filter, count, sort and paginate in MongoDB with an index; validate dates and pagination. |
| 13 | Attendance response serialization | The starter exposed Mongo `_id` as an `id`, contrary to the natural-key contract, and returned BSON datetimes in punch fields. Legacy missing `history`/`half_day` values were not normalized. | Inspect a `GET /attendance` response and seed a legacy record. | Return only contract fields, convert all instants—including nested audit values—to epoch milliseconds, and default missing fields. |
| 14 | Missing contract endpoints | Punch-out, regularization, monthly and department analytics, late leaderboard, department trend, and explain were only TODO comments. | Compare registered routes with `openapi.yaml`. | Implement all seven endpoints and their required aggregations and concurrency behavior. |
| 15 | Validation and errors | Most request/query values relied on permissive defaults, leaving invalid statuses, dates, page limits and timestamps unchecked. | Try invalid enum values, malformed dates, or page size 101. | Add Pydantic and FastAPI validation consistent with the contract and use 404/409/422/503 where appropriate. |
| 16 | Project verification | There was no test suite, and the review/decision files were empty templates. | Run `pytest`; inspect the documentation. | Add API/helper/pipeline tests and complete the review and design-decision documents. |

## Checked and retained

- Synchronous PyMongo is appropriate in these synchronous FastAPI route handlers; it does not block an async route.
- `PRESENT` as the punch-in default and the default shift strings match the contract.
- `load_dotenv()` uses its default `override=False`, so actual environment variables take precedence over `.env`.
- Removing `_id` from the starter's employee-create response was correct; the response still needed timestamp conversion.
